# 滴答笔记「标题 ⇄ 文件名」同步说明

本文记录本次针对 `Obsidian-DidaSync` 笔记同步的改进：新增可选设置 **「同步笔记标题到文件名」**，并修复「重命名文件被判定为删除」的问题。适用于分支 `feature/note-title-filename-sync`。

## 背景：原来的两个缺陷

1. **重命名 = 删除**：同步记录里保存的是文件的旧路径，重命名后旧路径失效，`LocalDeletionTracker` 会把它当作本地文件被删除，弹出删除确认；确认后还会删除远端笔记。
2. **远端改标题，本地文件名不变**：文件名由 `标题-<id 后 6 位>.md` 生成，且正文以 `## 标题` 重复标题。滴答端改标题后，下一次同步只更新正文标题行，文件名保持旧标题。

根本原因：查找本地文件依赖 `didaNoteSyncRecords.path` 与文件名，而不是笔记自身携带的 `didaNoteId`。

## 开关：设置 → DidaSync → 同步 → 滴答笔记同步

**同步笔记标题到文件名**（`didaNoteSyncTitleToFilename`，默认关闭）

开启后：

| 项目 | 行为 |
|---|---|
| 文件名 | 仅使用净化后的滴答标题，例如 `test.md`；不再追加 `-5213ea` |
| 正文 | 不再写入 `## 标题`，文件正文就是滴答笔记正文 |
| 标题匹配 | 标题 = 文件名；正文内容对应远端 `content` 字段 |
| 滴答改标题 | 下一次同步通过 `app.fileManager.renameFile()` 自动改名，`[[双向链接]]` 由 Obsidian 维护 |
| Obsidian 改名 | 约 1.5 秒防抖后触发一次「仅笔记」同步，把新文件名推送为远端标题 |
| 未命名笔记 | 远端标题为空时文件名为 `未命名.md` |
| 同名文件 | 自动使用 `标题 (1).md`、`标题 (2).md`… |
| 旧笔记 | 首次开启后的下一次同步自动整理：去掉 id 后缀、去掉正文标题行；内容与远端一致的笔记不会触发远端写入 |

关闭开关时保持 1.9.1 的行为（带 id 后缀、正文含 `## 标题`），但**重命名不再被误判为删除**。

## 匹配机制

- 每个同步文件在 frontmatter 中都有 `didaNoteId`，它是唯一身份。
- `NoteFileLocator` 每次同步只遍历一次笔记目录，优先读取 Obsidian `metadataCache` 的 frontmatter；只有缓存缺失（例如刚创建）时才读取文件内容，避免暴力读取整个仓库。
- 同步记录新增两个字段：
  - `localFileStem`：上次同步确认的文件名主干（含冲突后缀），用于检测「用户改名」；
  - `contentFormat`：`plain`（新格式）或 `heading`（旧格式），用于一次性迁移。

## 一次同步的决策顺序（开启开关时）

1. 用 `didaNoteId` 找到本地文件：先看记录路径，再按 id 在笔记目录中查找。找不到文件才视为删除。
2. 旧格式记录先迁移：剥离 `## 标题` 首行；与远端正文比较：
   - 相同：只规范化文件，不写远端；
   - 不同且远端未变：视为本地编辑，推送正文；
   - 不同且远端也变：按修改时间比较，胜者决定正文与标题。
3. 新格式记录：分别判断本地正文、本地文件名、远端正文、远端标题是否变化：
   - 仅本地变化：推送正文与标题；
   - 仅远端变化：写入正文，必要时改名；
   - 两端都变：沿用原有整篇冲突策略（时间戳可比较时胜者决定内容与标题）；
   - 都未变：不写文件、不调用 API。

## 防死循环

1. 插件自己调用 `renameFile` 前登记目标路径，`vault.on("rename")` 命中即忽略，不触发同步。
2. 改名后同步记录立即更新 `path` / `localFileStem` / `title`，下一次同步比较不到差异，不会重复推送。
3. 只有检测到真实差异才写入或调用 API；稳定状态下同步是幂等的。
4. 连续改名用 1.5 秒防抖合并；已有同步在跑时交给下一次自动同步。
5. 正常删除文件仍走原有「删除候选 + 人工确认」流程，不会误删远端。

## 迁移与前端事项

- 首次开启后，旧笔记会在下一次同步中被整理。迁移只改变本地文件，不改变远端内容（除非本地确实有编辑）。
- 写回文件时只替换 7 个 `dida*` frontmatter 键，用户或其它插件添加的 frontmatter（例如 `tags`）会原样保留。
- 关闭再重新开启开关是安全的：旧格式会重新识别并迁移，用户正文开头的 `##` 不会被误删。
- 记录里保存远端原始标题，空标题在界面上回退显示路径。

## 已知限制

- 两条笔记互换标题时，按顺序处理可能暂时保留 ` (1)` 后缀（不丢文件，可手动改名）。
- 冲突解除后不会自动把 `标题 (1).md` 收回到 `标题.md`。
- 整篇冲突时，内容胜者同时决定标题：本地胜 = 保留本地文件名并推送；远端胜 = 采用远端标题改名。
- 外部文件系统改名如果被 Obsidian 识别为「删除 + 新建」，事件可能不触发；此时依靠 `didaNoteId` 自愈与下一次同步收敛（最迟一个自动同步周期）。
- `未命名` 固定为中文，不随界面语言变化。

## 涉及文件

- `src/noteFilename.ts`：文件名净化、冲突名、旧标题行剥离等纯函数。
- `src/noteDocument.ts`：frontmatter/正文解析与渲染，保留用户 frontmatter。
- `src/sync/NoteFileLocator.ts`：基于 `metadataCache` 的 `didaNoteId` 索引。
- `src/managers/NoteSyncManager.ts`：双格式同步、迁移、改名、防循环。
- `src/sync/LocalDeletionTracker.ts`：按 `didaNoteId` 自愈重命名，避免误判删除。
- `src/main.ts`：注册 `vault.on("rename")` 并防抖调度笔记同步。
- `src/settings/views/sync-settings-view.ts`、`src/i18n.ts`：开关与文案。
- `tests/noteFilename.test.ts`、`tests/noteDocument.test.ts`、`tests/noteSyncManager.test.ts`：覆盖净化、解析、迁移、双向改名、冲突名、空标题、防循环与自愈。
